Case 04 / Car-rental system

Understand the booking flow before changing it.

At QQRIQ, I developed and extended an existing Laravel car-rental system. Booking, authentication, vehicle information, email notifications and payment integration all belonged to the same application, so a change started with understanding the code and expected behaviour.

Role & team
Software developer / QQRIQ
Period
January – September 2021
Focus
Booking flows & existing system behaviour
01 / Context

One booking touches several parts of a system.

The car-rental application already existed when I joined the work. It covered booking flows, user authentication, vehicle functionality, email notifications and payment integration.

Because these features were connected, extending the system also meant looking at the existing code and understanding how a change would fit with what was already there.

02 / Contribution

What I worked on.

  • Car-rental features: developed and extended booking, authentication, vehicle, email notification and payment functionality in Laravel.
  • Technical investigation: examined existing code and functional issues, then proposed and implemented solutions after aligning with the team.
  • Testing: tested the features I worked on and considered edge cases.
  • Separate project: investigated image-processing issues in another QQRIQ project that used ImageMagick.
03 / Challenges

Agree on the fix before changing the code.

When I found a functional issue in the existing system, I investigated how the code behaved, proposed a solution and agreed on an approach with the team before implementing it. That kept the expected result clear during the change.

In a separate image-processing project, I also joined client conversations to understand what the client needed and what behaviour they expected. That experience reinforced the same habit of making a vague request concrete before building a solution.
