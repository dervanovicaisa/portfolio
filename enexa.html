Case 01 / Enexa

Understanding the system behind the interface.

Frontend development for a virtual power plant platform, connecting trading concepts and permission-based forms with clear requirements and API behaviour.

Role & team
Web developer / ClickerTeam
Period
September 2024 – August 2026
Focus
Trading Desk, permissions & EDS forms
01 / Context

The interface was only the final step.

A trading interface needs to communicate more than the data on screen. Its forms and actions also reflect domain rules, access permissions and the behaviour of the underlying system.

My work covered Trading Desk and Admin UI behaviour, forms, data presentation and states. This is where frontend implementation meets the questions behind a requirement: what can the user do, under which conditions, and how should the interface explain the result?

02 / Contribution

Where I contributed.

  • Trading functionality: developed frontend features involving imbalance calculations, positions, commitments, orders, volumes and prices.
  • Requirements: refined Jira descriptions and subtasks, proposed acceptance criteria and clarified functionality with the Product Owner, Project Manager and backend developers.
  • API analysis: used Swagger/OpenAPI to understand available data and API behaviour before implementation.
  • Permissions and forms: worked on permissions and category-driven EDS forms, including investigating edge cases.
  • Validation and release support: supported testing, UAT and post-release issue investigation with PM, QA and DevOps.
03 / Working process

Clarify, implement, investigate.

Before implementation, I collaborated with product and engineering colleagues to clarify functionality. Jira descriptions, subtasks and proposed acceptance criteria helped make the expected behaviour explicit.

Swagger/OpenAPI connected those requirements to the data and behaviour exposed by the backend. Permissions, category-driven forms and edge cases were part of the implementation work.

My contribution also extended to testing and UAT, followed by investigating issues after release with PM, QA and DevOps.
