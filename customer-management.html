Case 03 / Application redesign

Find out how the old application works before redesigning it.

At Trid Tech, I helped move existing functionality into a new design. The designs showed what the screens should look like, but not everything the application already did. With limited documentation, I used the code and live application to understand what needed to be preserved.

Role & team
Web developer / Trid Tech
Period
February 2022 – January 2023
Focus
Existing behaviour & design migration
01 / Context

A design cannot explain every existing rule.

The Figma designs described the new appearance. They did not explain all the behaviour of the live application. Because the documentation was limited, rebuilding from the designs alone would have meant guessing how the features should work.

I read the existing code and tested different scenarios in the live application to learn what it actually did before adapting it to the new design.

02 / Contribution

What I worked on.

  • Existing behaviour: investigated the code to understand how the current features worked.
  • Live testing: tried different scenarios in the application and compared what happened with the new designs.
  • Team clarification: checked unclear details with the team rather than assuming an answer.
  • Redesign: rebuilt the functionality in the new interface while preserving the behaviour that needed to remain.
03 / Challenges

When the design left a question open.

The main challenge was discovering behaviour that was already in the product but missing from the designs and documentation. I used the code and live application together: one showed how a feature was implemented, while the other showed what a user actually experienced.

When those sources still did not answer a question, I checked with the team before rebuilding the feature. That helped preserve existing functionality instead of changing it by accident.

Illustrative questions

The decisions behind a redesign.

These questions illustrate the documented investigation process; they are not claims about specific production incidents.

01 / Current state

What does the old feature do?

If a control appears in the new design, what action does it perform in the live application?

02 / Scenarios

Does it always behave the same way?

Try more than one path through the old application before deciding what the new interface should reproduce.

03 / Decision

What needs team agreement?

If the design and observed behaviour do not answer the same question, clarify the expected result before rebuilding.

04 / Perspective

What I would bring to systems analysis.

This project showed me how to discover a system's current behaviour when documentation is incomplete. I would use the same approach in Business Systems Analysis: separate observation from assumption, confirm gaps with the team and define what should change.
